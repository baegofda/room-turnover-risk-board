# 당일 운영 리스크 보드

청소 인력의 작업 순서를 따라가며 객실마다 준비가 끝나는 시각을 계산하고, **체크인 전에 준비되지 않을 객실을 13:00 객실 안내 전에 미리 드러내는** 관제 보드예요. 핸디즈 어반스테이 과제로 만들었습니다.

- 배포 주소: https://room-turnover-risk-board.vercel.app
- 예시 데이터: 지점 1곳, 객실 12실, 청소 인력 2명, 판정 시각 10:30

## 풀려는 문제

"체크인까지 남은 시간이 청소 시간보다 긴가"는 객실 하나씩 보면 조건문 하나로 끝나요. 실제로는 인력이 한정돼 있어서, 11시에 객실이 한꺼번에 비면 뒤 순번 객실은 계속 기다립니다. 예시 데이터에서 객실을 하나씩 떼어 보면 위험은 0실인데, 청소 순서까지 따라가면 2실이 체크인에 늦어요.

무인 운영 지점은 13:00에 손님에게 객실 호수와 도어락 비밀번호를 보내요. 그 전에 알면 다른 객실을 배정하거나 인력을 먼저 보내도 손님에게 다시 연락할 필요가 없고, 그 뒤에 알면 손님에게 다시 연락해야 합니다. 그래서 이 보드는 늦어질 객실을 **언제까지 알아야 싸게 대응할 수 있는지**와 함께 보여 줘요.

자세한 배경은 [03. 문제 정의](./docs/03-problem.md)에 있어요.

## 화면에서 볼 수 있는 것

- **간트:** 객실마다 퇴실, 청소 대기, 예상 청소, 다음 체크인, 13:00 안내 시각을 한 시간축에 그려요.
- **위험 객실 카드:** 왜 늦는지(대기, 퇴실 지연, 청소 지연, 긴 청소)와 지금 할 수 있는 대응을 보여 줘요.
- **시뮬레이터:** 판정 시각을 넘기고, 청소 인력 수를 바꾸고, 퇴실과 청소 시작, 완료를 기록하면 같은 판정 로직으로 다시 계산해요. 기록이 늦으면 판정이 어떻게 바뀌는지 직접 볼 수 있습니다.

## 실행

Node.js 24와 pnpm 10이 필요해요.

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

```bash
pnpm test         # 판정 로직 테스트 (Vitest)
pnpm lint         # ESLint
pnpm typecheck    # TypeScript
pnpm build        # 프로덕션 빌드
```

입력 데이터는 [`samples/busy-day.json`](./samples/busy-day.json)이고, 이 입력의 기대 결과를 [`samples/busy-day.expected.json`](./samples/busy-day.expected.json)에 고정해 테스트로 비교해요.

## 구조

```
src/core/     판정 로직. React와 Next.js를 모르는 순수 함수예요
src/app/      Next.js 화면. core의 index.ts가 공개한 함수만 불러요
samples/      입력 예시와 기대 결과
tests/core/   명세 규칙, 현장 기록, 시나리오 테스트
docs/         조사부터 한계까지의 문서
```

판정 로직은 현재 시각을 읽지 않고 입력의 판정 시각(`asOf`)만 써요. 같은 입력이면 언제 실행해도 같은 결과가 나옵니다. 이 규칙은 ESLint로 막아 두었어요.

## AI 활용과 검토

| 도구 | 쓴 곳 |
|---|---|
| Claude Code | 회사 조사와 원문 대조, 설계 논의, 문서 초안, 구현과 테스트 |
| Perplexity | 수익성과 경쟁력 추가 조사 |
| ChatGPT | 설계 리뷰. 함께 만든 설계를 다른 모델에게 보여 주고 허점을 찾게 했어요 |
| Claude (GitHub Action) | PR마다 자동 코드 리뷰 |

AI가 낸 결과는 그대로 쓰지 않고, 사실은 원문으로, 판정 규칙은 테스트로, 화면은 직접 실행해서 확인했어요. 대표 사례는 이렇습니다.

- **원문 대조:** 검색 요약의 "청소 일 평균 200회"가 기사 원문에서는 "주 200회"여서 원문 기준으로 고쳤어요.
- **설계 문제 제기:** 처음 판정은 "체크인 2시간 전까지 청소가 끝났는가" 같은 객실별 비교였어요. 이걸로는 인력 때문에 늦는 객실을 잡지 못해서 청소 순서를 따라가는 계산으로 바꿨습니다.
- **다른 모델의 리뷰 검증:** ChatGPT가 기본 배정 규칙의 반례를 들었는데 실제로는 성립하지 않았어요. 지적은 받아들이고, 객실이 비는 시각이 다를 때 틀리는 반례로 다시 만들었습니다.
- **보수적인 규칙으로 수정:** 늦어진 퇴실과 청소를 "판정 시각에 끝난다"고 본 계산이 위험을 가린다는 걸 찾아, 판정 시각부터 15분 더 걸린다고 보는 규칙으로 명세와 코드를 함께 바꿨어요.

## 작업 방식

작업은 Linear 이슈 단위로 나누고, 이슈 번호를 브랜치 이름과 커밋 제목에 붙였어요. 이슈마다 PR을 열고 Claude 자동 리뷰를 돌렸습니다. 리뷰와 코드 규칙은 [`AGENTS.md`](./AGENTS.md)와 [`.claude/rules`](./.claude/rules)에 있어요.
