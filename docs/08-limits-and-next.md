# 08. 한계와 다음 단계

이번 결과물이 무엇을 하지 않는지, 실제로 쓰려면 무엇이 더 필요한지 정리해요. 일부러 뺀 것과 한계를 나눠 적습니다.

## 일부러 하지 않은 것

| 하지 않은 것 | 이유 |
|---|---|
| 청소 배정 최적화 | 보드의 역할은 "지금 순서대로 가면 어떻게 되는지"를 보여 주는 거예요. 판정이 맞는지 먼저 확인해야 최적화도 의미가 있습니다 |
| 청소 시간 AI 예측 | 실제 청소 기록이 없어요. 만든 데이터로 학습하면 내가 넣은 규칙을 다시 찾을 뿐이라 함수로만 분리해 뒀어요 |
| 하우스키퍼별 청소 속도 | 같은 이유로 근거가 없어요. `estimateCleaningMinutes`에 `staffId` 자리만 만들어 두었습니다 |
| 점검 실패, 상태 갱신 없음 판정 | 명세에 규칙을 정하지 않았어요. 현장 기록에도 버튼을 두지 않았습니다 |
| PMS, OTA, 도어락 연동 | 실제 API가 없어요. 입력 JSON을 경계로 두고, 연동할 때는 이 JSON을 만드는 쪽만 바꾸면 돼요 |
| 저장소(DB)와 실시간 동기화 | 판정 로직의 정확성과 상관이 없어요. 공개 주소에서 평가자끼리 데이터가 섞이는 문제도 피했습니다 |
| 알림 발송 | 틀린 알림은 금방 무시당해요. 판정이 실제 지연을 잘 맞히는지 먼저 확인해야 합니다 |
| 여러 지점과 권한 | 지점 1곳에서 판정이 맞는지가 먼저예요 |

## 한계

**청소 시간은 모두 가정값이에요.** 객실 타입별 기본 시간(스튜디오 50분, 트윈 65분)과 숙박 일수, 인원에 따른 가산은 근거 있는 값이 아니에요. 판정의 정확도는 이 값에 크게 좌우됩니다.

**기본 배정 규칙은 최선이 아니에요.** 배정표가 없을 때 "먼저 손이 빈 사람이, 다음 손님이 빨리 오는 객실부터" 맡는 규칙을 써요. 객실이 비는 시각이 다르면 이 규칙이 더 나쁜 순서를 고를 수 있어요. 예를 들어 11:00에 빈 객실 A(16:00 체크인, 120분)를 먼저 잡으면, 11:10에 비고 12:00에 체크인하는 객실 B(30분)가 늦습니다. 그래서 인력을 늘려도 결과가 항상 나아진다고 보장하지 않아요. 화면에도 이 점을 적어 두었습니다.

**기록이 없으면 늦는다고 봐요.** 체크아웃 시각이 지났는데 퇴실 기록이 없거나, 예상 청소 시간이 지났는데 완료 기록이 없으면 지금부터 15분 뒤로 잡아요. 늦어질 객실을 가리지 않으려는 선택이지만, 현장 기록이 자주 빠지면 위험이 실제보다 많이 나옵니다.

**시뮬레이터는 실제 앱이 아니에요.**

- 청소 시작을 누르면 그 순간 화면에 보이는 예상 담당자로 기록해요. 그래서 출근 전인 인력이 청소를 시작한 것으로 기록될 수 있어요. 실제 앱에서는 누른 사람이 담당자라 생기지 않는 문제입니다.
- 늘린 인력은 첫 번째 인력과 같은 시각에 출근한다고 가정해요.
- 상태는 브라우저 메모리에만 있어서 새로고침하면 처음으로 돌아가요.
- 판정 시각은 22:00까지만 넘길 수 있어요. 날짜가 바뀌면 "오늘 청소할 객실"이 달라지기 때문입니다.

**하루, 한 지점만 다뤄요.** 자정을 넘기는 체크인은 다루지만, 여러 날에 걸친 계획이나 지점 사이의 인력 이동은 다루지 않아요.

## 실제로 쓰려면

1. **청소 기록부터 쌓아요.** 하우스키퍼의 청소 시작과 완료 기록이 있으면 `estimateCleaningMinutes`를 실제 값으로 바꾸고, 판정이 실제 지연을 얼마나 맞혔는지 잴 수 있어요. [06. 작업 계획과 검증](./06-plan.md)의 가설 H1~H4를 검증하는 데이터도 여기서 나옵니다.
2. **현장 기록을 서버에 저장해요.** `applyEvent`는 이벤트를 받아 입력을 갱신하는 순수 함수예요. 이벤트를 저장소에 쌓고 같은 함수로 상태를 다시 만드는 구조로 옮기면 판정 로직은 바꾸지 않아도 됩니다.
3. **퇴실은 PMS와 도어락에서 받아요.** 지금은 버튼으로 흉내 냈지만, 실제로는 자동으로 들어와야 하는 기록이에요.
4. **점검 실패와 상태 갱신 없음 규칙을 정해요.** 명세에 규칙을 더하고 테스트부터 씁니다.
5. **그다음에 배정을 손봐요.** 판정이 믿을 만해진 뒤에, 위험 객실을 줄이는 배정 순서를 제안하는 기능을 검토해요.
