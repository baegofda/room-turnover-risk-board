# AI 활용과 검토 기록

과제를 준비하면서 AI 결과를 검토하고 고친 사례를 일어난 순서대로 모아 둡니다.

## 도구와 역할

| 도구 | 쓴 곳 |
|---|---|
| Claude Code | 회사 기본 조사와 원문 대조, 설계 논의, 문서 초안, 구현과 테스트, PR 작성 |
| Perplexity | 11/1 수익성과 경쟁력 추가 조사 |
| ChatGPT | 설계 리뷰. Claude Code와 함께 만든 설계를 다른 모델에게 보여 주고 허점을 찾게 했어요 |
| Claude (GitHub Action) | PR마다 자동 코드 리뷰. 리뷰 기준은 [`AGENTS.md`](../AGENTS.md)에 있어요 |

한 도구의 결과를 다른 도구와 원문으로 다시 확인하는 구조로 썼어요. AI가 낸 결과는 그대로 쓰지 않고, 사실은 원문으로, 판정 규칙은 테스트로, 화면은 직접 실행해서 확인했습니다.

## 조사와 설계

| # | 상황 | AI가 낸 것 | 검토하고 바꾼 것 |
|---|---|---|---|
| 1 | 회사 조사 (Claude Code) | 검색 요약에 "청소 일 평균 200회"라고 나왔어요 | 원문 기사를 확인하니 "주 200회"였습니다. 원문 기준으로 고쳤어요 |
| 2 | 회사 조사 (Claude Code) | "어반라이프"라는 브랜드명이 나왔어요 | 출처 정확도가 낮아 목록에서 뺐습니다 |
| 3 | Perplexity 리서치 검증 | AI 가격 책정이 "경쟁 숙소 가격과 점유율"을 반영한다고 적혀 있었어요 | 인터뷰 원문은 "경쟁 호텔 가격을 따라가는 수준이 아니라 내부 운영 데이터"를 강조합니다. 원문 표현을 쓰기로 했어요 |
| 4 | 회사 조사 검증 | 10/28 조사에서 플라트 라이프를 1개월, 3개월 단위로 정리해 두었어요 | 호스트 안내 페이지 기준으로 1주에서 28주로 고쳤습니다 |
| 5 | Perplexity 리서치 검증 | 장기체류 호텔 시장 규모(2024년 7억 달러, 2030년 13억 달러)와 앱 기능, 운영 자동화 설명을 제시했어요 | 시장 규모는 출처가 없어서 뺐고, 블로그가 출처인 내용은 원문을 열 수 없어 "확인 못 함"으로 표시했습니다. 당일 시각표는 지점 안내 페이지로 따로 확인한 값만 썼어요 |
| 6 | 판정 규칙 설계 | 첫 규칙은 "체크인 2시간 전까지 청소가 끝났는가" 같은 객실별 상태 비교였어요 | 직접 "너무 간단하지 않나"라고 문제를 제기했고, 인력 순서를 반영한 예상 준비 완료 시각 계산으로 바꿨습니다 |
| 7 | 정비 시간 AI 예측 | 청소 시간을 모델로 예측하는 안을 검토했어요 | 실제 기록 없이 만든 데이터로 학습하면 내가 넣은 규칙을 다시 찾을 뿐이라서 빼고, 교체할 수 있는 함수로만 남겼어요 |
| 8 | 개념 페이지 | 시뮬레이션 기본값을 청소 인력 3명으로 잡았어요 | 계산을 돌려 보니 주의 1실만 나와 요점이 약했습니다. 인터뷰의 인력 비율(약 200실에 5~7명)로 보면 12실에 2명이 더 현실에 가까워서 2명으로 바꿨어요 |
| 9 | ChatGPT 설계 리뷰 | 탐욕적 배정의 한계를 지적하면서 반례로 "A 15:00 체크인 120분, B 14:00 체크인 30분"을 들었어요 | 지적은 받아들였지만 반례가 틀렸습니다. 두 객실이 동시에 비어 있으면 어느 순서로 해도 둘 다 제시간에 끝나요. 객실이 비는 시각이 다를 때(B가 11:10에 비고 12:00 체크인) 틀린다는 반례로 다시 만들었습니다 |
| 10 | ChatGPT 설계 리뷰 | 운영 시나리오 비교로 인력 수 변경, 작업 순서 변경, 체크인 시각 조정을 제안했어요 | 인력 수 비교만 받았습니다. 순서 변경은 범위에서 뺀 배정 최적화이고, 체크인 시각 조정은 사람이 할 대응이라 뺐어요 |
| 11 | ChatGPT 설계 리뷰 | 13시 전후로 대응을 나누자고 제안했어요 | 받아들였고, 검토하다가 기존 페이지가 예상 완료 시각을 13시와 비교하고 있다는 점을 찾았습니다. 대응을 정하는 건 판정 시각(`asOf`)이라서 기준을 고쳤어요 |
| 12 | ChatGPT 설계 리뷰 | 경계값 테스트("여유 시간이 정확히 0분" 등)를 제안했어요 | 테스트를 쓰기 전에 경계값의 의미부터 정했습니다. 0분은 주의, 30분은 정상, 13:00 정각 완료는 안내 전으로 봐요 |
| 13 | ChatGPT 설계 리뷰 | 점검 실패 규칙은 범위에서 뺐는데 시뮬레이터 버튼과 `applyEvent`에는 남아 있다는 모순을 짚었어요 | 받아들였습니다. 버튼과 입력 필드를 함께 빼고 다음 단계로 옮겼어요 |
| 14 | ChatGPT 설계 리뷰 | 객실 동률일 때의 우선순위(체크인, 퇴실, 객실 번호)를 제안했어요 | 받아들이면서, 예시 상황에 있던 "두 인력이 같은 시각에 빔"에 대한 규칙이 빠져 있어 인력 ID 오름차순 규칙을 직접 더했어요 |
| 15 | ChatGPT 설계 리뷰 | 인력 수 비교는 인력 수만 바꿔 독립적으로 다시 계산하자고 했어요 | 받아들이면서, 배정표가 있을 때 현재 결과(배정표 기준)와 비교 결과(기본 규칙)가 섞이는 문제를 찾아 모든 행을 기본 규칙으로 계산하기로 했습니다 |
| 16 | ChatGPT 설계 리뷰 | 배포를 "여유가 있다면" 할 일로 두고, 문서를 마지막에 정리하자고 했어요 | 배포는 마감 직전 변수를 줄이려고 프로젝트 설정 직후로 앞당겼고, 문서는 미루지 않되 1시간 안쪽으로 시간을 정했어요 |

## 구현

| # | 상황 | AI가 낸 것 | 검토하고 바꾼 것 |
|---|---|---|---|
| 17 | 지연 판정 규칙 | 퇴실이나 청소가 예정보다 늦어지면 판정 시각에 끝난다고 계산했어요 | "퇴실 안 한 것도 보수적으로 봐야 하지 않나"라고 물었고, 판정 시각부터 15분 더 걸린다고 보는 규칙으로 명세와 코드를 함께 바꿨어요 |
| 18 | 자동 리뷰 설정 | 자동 리뷰가 `AGENTS.md`를 읽는다고 보고했어요. 근거는 `AGENTS.md`를 바꾼 PR에서 리뷰가 그 내용을 언급했다는 점이었어요 | 그 파일이 diff에 있었으니 근거가 되지 못했어요. 리뷰 도구가 기본으로 읽는 `CLAUDE.md`에서 `AGENTS.md`를 불러오도록 고쳤습니다 |
| 19 | 판정 구현 | 아직 시작하지 않은 청소가 판정 시각보다 이른 시각에 시작하는 것으로 계산될 수 있었어요 | 이미 지난 시각에 청소를 시작할 수는 없으니 판정 시각 이후에만 시작하도록 정하고 테스트로 고정했어요 |
| 20 | 빌드 | Next.js 16 기본 설정(Cache Components)이 시간대 객체를 "렌더링마다 바뀌는 값"으로 보고 빌드를 막았어요 | 판정은 입력이 고정이라 결과가 바뀌지 않아요. 원인을 확인하고 해당 설정을 껐습니다 |
| 21 | 관제 화면 | 첫 화면은 객실 카드 목록뿐이었어요. 주제를 정할 때 만든 소개 페이지의 시간축 간트가 빠졌어요 | 직접 실행해 보고 "그 화면처럼 나오는 거 아니었냐"고 짚었어요. 간트와 "따로 보면 0실, 순서까지 보면 2실" 대비 문장을 넣었고, 소개 페이지처럼 화면에서 따로 계산하지 않고 테스트한 `evaluate`를 그대로 쓰게 했어요 |
| 22 | 현장 기록 테스트 | 정상 객실에도 이유 코드가 붙는다고 가정하고 테스트를 썼다가 실패했어요 | 명세상 이유는 위험과 주의에만 붙어요. 테스트가 틀린 것이라 이유 코드 대신 계산된 시각을 확인하도록 고쳤어요 |
| 23 | 현장 기록 화면 | 퇴실 버튼을 "하우스키퍼 시점" 아래에 두었어요 | "퇴실도 하우스키퍼가 하나?"라고 짚었어요. 무인 운영에서 퇴실은 손님 앱, 도어락, PMS의 기록이라 손님 기록과 하우스키퍼 기록으로 나눴어요 |
| 24 | 판정 이유 문구 | 청소 시간을 늘린 이유를 "오래 묵었거나 인원이 많아"로 뭉뚱그렸어요 | 무엇 때문에 몇 분을 더했는지 알 수 없어서, 해당한 조건과 더한 시간을 함께 적도록 바꾸고 테스트를 먼저 추가했어요 |
| 25 | 커밋 | `git commit -a`로 개발 서버가 자동으로 바꾼 `AGENTS.md`까지 커밋했어요 | 이력을 덮어쓰지 않고 되돌리는 커밋을 따로 남겼어요 |

## 문서

문서 초안도 AI가 썼고, 사람이 읽으며 고친 원칙은 이래요.

- "사실이 아니라 판단입니다"처럼 문서 자체를 설명하는 문장과 3인칭 "지원자" 표현을 뺐어요.
- 회사에 대한 사실에는 출처를 달고, 가정한 값은 가정이라고 적었어요.
- 조사 방식은 실제로 쓴 도구 그대로(Claude Code와 Perplexity) 적었어요.
