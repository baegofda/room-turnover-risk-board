# 04. 판정 명세

지금 이 순간의 객실 상황을 넣으면 청소 순서대로 따라가 보고, 객실마다 체크인 전에 준비될지를 이유와 함께 알려 줘요. 이 문서는 그 계산 방법을 정한 약속입니다. 규칙마다 테스트를 붙이고 코드와 이 문서가 다르면 코드를 고쳐요.

문제와 가설은 [03. 문제 정의](./03-problem.md)에 있어요.

## 한눈에 보기

1. 지금 상황을 한 장의 스냅샷으로 받아요.
2. 오늘 청소할 객실을 골라요.
3. 손님이 언제 나가는지 정해요.
4. 청소가 얼마나 걸릴지 어림해요.
5. 청소 순서를 따라가며 객실마다 준비가 끝나는 시각을 구해요.
6. 체크인까지 여유가 얼마나 남는지 보고 정상, 주의, 위험을 정해요.
7. 지금 시각에 할 수 있는 대응과 늦어지는 이유를 붙여요.

## 1. 입력: 지금 상황의 스냅샷

"10시 30분 현재 상황"을 사진 한 장처럼 받아요. 사진을 찍은 시각이 **판정 시각(`asOf`)**입니다. 판정 시각은 예상 값이 아니라 실제로 상황을 확인한 시각이고 코드는 현재 시각을 따로 읽지 않아요. 그래서 같은 입력을 넣으면 언제 실행해도 같은 결과가 나옵니다.

```json
{
  "asOf": "2026-11-01T10:30:00+09:00",
  "policy": {
    "roomNoticeAt": "13:00",
    "warnSlackMinutes": 30,
    "imminentMinutes": 60,
    "overdueMinutes": 15,
    "roomTypes": {
      "studio": { "baseCleaningMinutes": 50 },
      "twin": { "baseCleaningMinutes": 65 }
    }
  },
  "rooms": [
    { "no": "1203", "type": "studio" }
  ],
  "stays": [
    {
      "id": "R-1001",
      "roomNo": "1203",
      "checkIn": "2026-10-25T16:00:00+09:00",
      "checkOut": "2026-11-01T11:00:00+09:00",
      "checkedOutAt": null,
      "guests": 2
    },
    {
      "id": "R-1002",
      "roomNo": "1203",
      "checkIn": "2026-11-01T14:00:00+09:00",
      "checkOut": "2026-11-03T11:00:00+09:00",
      "guests": 1
    }
  ],
  "housekeeping": {
    "staff": [
      { "id": "hk-1", "availableFrom": "2026-11-01T11:00:00+09:00" }
    ],
    "tasks": [
      {
        "roomNo": "1203",
        "assignee": "hk-1",
        "order": 1,
        "startedAt": null,
        "finishedAt": null
      }
    ]
  }
}
```

| 항목 | 뜻 |
|---|---|
| `asOf` | 판정 시각이에요 |
| `policy` | 지점마다 다를 수 있는 규칙이에요. 아래 표에서 따로 설명해요 |
| `rooms` | 객실 번호와 객실 타입이에요 |
| `stays` | 숙박마다 예정 체크인, 예정 체크아웃, 실제 퇴실 시각(`checkedOutAt`, 아직 안 나갔으면 `null`), 인원이에요. 얼리 체크인과 레이트 체크아웃은 따로 표시하지 않고 바뀐 시각으로 받아요 |
| `housekeeping.staff` | 청소 인력과 일을 시작할 수 있는 시각이에요 |
| `housekeeping.tasks` | 없어도 돼요. 배정표(누가 어떤 순서로 맡는지)와 진행 상황(청소 시작, 완료 시각)이에요 |

| 지점 규칙 | 뜻 | 가정값 |
|---|---|---|
| `roomNoticeAt` | 손님에게 객실 호수와 도어락 안내를 보내는 시각 | 13:00 |
| `warnSlackMinutes` | 여유가 이보다 적으면 주의 | 30분 |
| `imminentMinutes` | 체크인까지 이만큼 이하로 남으면 체크인 임박 | 60분 |
| `overdueMinutes` | 예정 시각을 넘긴 퇴실이나 청소가 지금부터 더 걸린다고 보는 시간 | 15분 |
| `roomTypes` | 객실 타입별 기본 청소 시간 | 스튜디오 50분, 트윈 65분 |

손님 이름, 연락처, 요금, 예약 채널은 받지 않아요.

### 받지 않는 입력

아래 경우는 계산하지 않고 오류로 돌려보내요.

- 시각에 `+09:00`이 붙어 있지 않아요
- 청소 인력이 한 명도 없어요
- 같은 객실의 숙박 기간이 겹쳐요
- 체크아웃이 체크인보다 이르거나 같아요
- 같은 객실 번호가 두 번 나와요
- 숙박이나 작업이 없는 객실을 가리키거나 작업이 없는 청소 인력을 가리켜요
- 객실 타입이 `roomTypes`에 없어요

## 2. 오늘 청소할 객실 고르기

- 오늘 체크아웃하는 손님이 있는 객실을 골라요.
- 그 객실에 다음으로 들어오는 숙박을 찾아요. 다음 날 새벽에 들어와도 다음 숙박으로 봐요.
- 다음 숙박이 없는 객실도 청소는 하지만 서두를 이유가 없어서 등급을 매기지 않아요(`none`).
- 오늘 아무도 나가지 않는 연박 객실은 고르지 않아요.

## 3. 손님이 언제 나가는지 정하기

| 상황 | 나가는 시각 |
|---|---|
| 이미 나갔어요 (`checkedOutAt` 있음) | 실제로 나간 시각 |
| 아직 체크아웃 시간 전이에요 | 예정 체크아웃 시각 |
| 체크아웃 시간이 지났는데 아직 안 나갔어요 | 판정 시각 + `overdueMinutes`. 퇴실 지연 이유를 붙여요 |

마지막 줄이 중요해요. 이미 늦어진 퇴실을 "지금 바로 나간다"고 보면 실제로는 더 늦어질 객실을 놓치게 돼서 지금부터 조금 더 걸린다고 보수적으로 계산합니다.

## 4. 청소 시간 어림하기

`estimateCleaningMinutes(room, stay, staffId?)`가 계산해요.

- 객실 타입의 기본 청소 시간에서 시작해요.
- 직전 숙박이 3박 이상이면 10분, 7박 이상이면 20분을 더해요.
- 인원이 3명 이상이었으면 10분을 더해요.

예를 들어 7박 뒤 나가는 스튜디오는 50분 + 20분 = 70분이에요. 지금은 가정값이고 실제 청소 기록이 쌓이면 이 함수만 바꾸면 됩니다. `staffId`는 사람별 차이를 넣을 자리로만 두고 지금은 쓰지 않아요.

## 5. 청소 순서를 따라가 보기

이 문서의 핵심이에요. 청소 인력이 객실을 하나씩 맡아 가는 과정을 그대로 따라가서 객실마다 준비가 끝나는 시각을 구해요. 앞 순번 객실이 끝날 때까지 기다리는 시간도 여기서 드러납니다.

**배정표가 있으면 그대로 따라요.** 오늘 청소할 모든 객실에 담당자(`assignee`)와 순서(`order`)가 있을 때만이에요. 하나라도 빠져 있으면 배정표를 쓰지 않고 아래 기본 규칙으로 계산하고 결과에 그렇게 표시해요.

**기본 규칙**

1. 손이 가장 먼저 비는 청소 인력을 골라요. 같은 시각에 비는 사람이 여럿이면 인력 ID 순서로 골라요.
2. 그 시각까지 비어 있는 객실 가운데 **다음 손님이 가장 빨리 들어오는 객실**을 맡겨요. 다음 손님이 없는 객실은 맨 뒤로 미뤄요.
3. 다음 손님이 들어오는 시각이 같으면 먼저 빈 객실을, 그것도 같으면 객실 번호 순서로 골라요.
4. 비어 있는 객실이 하나도 없으면 가장 먼저 비는 객실의 시각까지 기다려요.

3번처럼 순서가 같을 때의 규칙까지 정해 둔 건, 같은 입력이면 항상 같은 결과가 나오게 하려는 거예요.

**이미 청소 중인 객실**

- 청소가 끝났으면(`finishedAt` 있음) 그 시각에 준비가 끝난 거예요.
- 청소를 시작했으면(`startedAt`만 있음) 그 사람은 이 객실부터 마쳐요. 끝나는 시각은 시작 시각 + 청소 시간이에요.
- 그 시각이 이미 지났는데 아직 안 끝났다면 퇴실 지연과 마찬가지로 판정 시각 + `overdueMinutes`로 보고 청소 지연 이유를 붙여요.

## 6. 정상, 주의, 위험 정하기

> 여유 시간 = 다음 손님 체크인 시각 − 준비가 끝나는 시각

| 여유 시간 | 등급 |
|---|---|
| 0분보다 적어요 (손님이 먼저 와요) | 위험 (`risk`) |
| 0분 이상, 30분 미만 | 주의 (`warn`) |
| 30분 이상 | 정상 (`ok`) |
| 다음 손님이 없어요 | 판정 없음 (`none`) |

30분은 `warnSlackMinutes` 값이에요. 경계에 딱 걸리는 경우는 이렇게 정했어요.

| 경계 | 판정 | 이유 |
|---|---|---|
| 여유가 정확히 0분 | 주의 | 체크인 시각에 맞춰 끝나면 늦은 건 아니에요 |
| 여유가 정확히 30분 | 정상 | 30분 미만부터 주의예요 |
| 정확히 13:00에 준비가 끝남 | 안내 전에 준비됨 | 안내 시각과 같으면 안내 전에 준비된 것으로 봐요 |
| 나가는 시각과 들어오는 시각이 같음 | 위험 | 청소할 시간이 없어요 |

## 7. 대응 시점과 이유 붙이기

### 지금 할 수 있는 대응

같은 위험이라도 판정 시각이 언제냐에 따라 할 수 있는 일이 달라요. 조건이 겹칠 수 있어서 위에서부터 먼저 맞는 하나만 골라요.

| 순서 | 대응 시점 | 조건 | 관제 담당자가 할 일 |
|---|---|---|---|
| 1 | 체크인 임박 (`imminent`) | 체크인까지 60분 이하로 남았거나 이미 지났어요 | 대체 객실 확보, 현장 대응 |
| 2 | 안내 후 (`after_notice`) | 판정 시각이 13:00이거나 그보다 늦어요 | 손님에게 연락, 객실 변경 안내 |
| 3 | 안내 전 (`before_notice`) | 그 밖의 경우예요 | 손님 모르게 객실 변경, 청소 인력 조정 |

60분은 `imminentMinutes`, 13:00은 `roomNoticeAt` 값이에요.

### 늦어지는 이유

주의나 위험인 객실에는 이유를 하나 이상 붙여요. "위험" 한 단어로 끝나지 않게 하려는 거예요.

| 코드 | 언제 붙이나 | 문장 예시 |
|---|---|---|
| `projected_late` | 위험일 때 | 체크인 14:00까지 청소가 끝나지 않아요. 예상 완료는 14:40입니다 |
| `tight_slack` | 주의일 때 | 체크인 16:00 전에 끝나지만 여유가 20분뿐이에요 |
| `queue_wait` | 손님이 나간 뒤 청소 시작까지 기다렸을 때 | 앞 순번 객실 때문에 퇴실 후 1시간 10분을 기다려요 |
| `checkout_delayed` | 체크아웃 시간이 지났는데 안 나갔을 때 | 체크아웃 11:00이 지났는데 아직 퇴실하지 않았어요 |
| `cleaning_overrun` | 예상 청소 시간이 지났는데 안 끝났을 때 | 예상 청소 시간을 30분 넘겼는데 아직 끝나지 않았어요 |
| `long_cleaning` | 오래 묵었거나 인원이 많아 청소가 길어질 때 | 7박 뒤 퇴실이라 기본 50분에 20분을 더해 1시간 10분으로 잡았어요 |

## 결과

```json
{
  "asOf": "2026-11-01T10:30:00+09:00",
  "assignment": "schedule",
  "summary": { "risk": 1, "warn": 1, "ok": 8, "none": 1 },
  "rooms": [
    {
      "roomNo": "1203",
      "level": "risk",
      "responseWindow": "before_notice",
      "nextCheckIn": "2026-11-01T14:00:00+09:00",
      "projectedReadyAt": "2026-11-01T14:40:00+09:00",
      "slackMinutes": -40,
      "readyBeforeNotice": false,
      "assignee": "hk-1",
      "reasons": [
        { "code": "projected_late", "message": "체크인 14:00까지 청소가 끝나지 않아요. 예상 완료는 14:40입니다" },
        { "code": "long_cleaning", "message": "7박 뒤 퇴실이라 기본 50분에 20분을 더해 1시간 10분으로 잡았어요" }
      ]
    }
  ]
}
```

- `assignment`는 배정표를 따랐으면 `schedule`, 기본 규칙을 썼으면 `default`예요.
- 객실은 여유가 적은 순서로 보여 줘요. 판정 없음은 맨 뒤에 둬요.
- 시각은 입력과 같은 형식(`+09:00`)으로 돌려줘요.

## 시간 계산

- 입력 시각은 `+09:00`이 붙은 ISO 8601만 받아요.
- 계산할 때는 모든 시각을 숫자(epoch 밀리초)로 바꿔요. 그래서 자정을 넘겨 들어오는 손님도 날짜 경계에서 틀리지 않아요.
- `13:00`처럼 시각만 있는 지점 규칙은 판정 날짜에 붙여서 계산해요. 한국은 서머타임이 없어서 `+09:00`으로 고정해도 됩니다.
- 화면에 보여 줄 때만 한국 시간으로 다시 바꿔요.

## 기본 규칙의 한계

기본 규칙은 현장이 지금 일하는 방식을 흉내 낸 것이라 가장 좋은 순서를 보장하지는 않아요. 객실이 비는 시각이 서로 다를 때 틀릴 수 있어요.

| 객실 (청소 인력 1명) | 비는 시각 | 다음 체크인 | 청소 시간 |
|---|---|---|---|
| A | 11:00 | 16:00 | 120분 |
| B (퇴실 지연) | 11:10 | 12:00 | 30분 |

11:00에 맡을 수 있는 객실이 A뿐이라 기본 규칙은 A부터 잡아요. 그러면 B는 13:00에야 시작해서 12:00 체크인을 넘겨요. 10분만 기다렸다가 B부터 하면 B는 11:40, A는 13:40에 끝나서 둘 다 제시간이에요. 이 사례는 테스트로 남겨서 기본 규칙이 이렇게 움직인다는 걸 확인해 둬요.

같은 이유로 "청소 인력을 늘리면 위험 객실이 줄어든다"도 이 규칙에서는 항상 맞지는 않아요. 일정 계산에서는 사람을 늘렸는데 결과가 나빠지는 경우가 알려져 있습니다.

## 이번에 다루지 않는 것

- 점검에서 고장이나 비품 누락이 나와 다시 청소하는 경우는 다루지 않아요
- 상태가 오래 바뀌지 않아 입력이 빠졌을 가능성을 잡는 규칙은 다음 단계로 미뤄요
- 청소 순서나 배정을 가장 좋게 바꿔 주는 기능은 만들지 않아요
- 청소 인력의 휴식과 층간 이동 시간은 청소 시간에 들어 있다고 봐요
